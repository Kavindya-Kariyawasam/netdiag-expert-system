# NetDiag - IT & Computer Network Troubleshooting Expert System

A rule-based expert system, that diagnoses computer hardware, operating system, and local area network faults from user-reported symptoms.

---

## 1. System Overview

NetDiag strictly separates domain-specific knowledge from inference execution, matching the classical expert system reference architecture:

```
[ Browser GUI / Terminal CLI ] <---> [ Flask app.py / cli.py ]
                                              |
                                              v
                                      [ engine.py ] (Inference Engine)
                                        - forward_chain()
                                        - BackwardChainer
                                        - explain_how() / why_ask()
                                        - explain_why_not()
                                              |
                                              v
                                      [ kb.py ] (Knowledge Base)
                                        - 30 askable leaf facts
                                        - 4 intermediate hypotheses
                                        - 23 final diagnoses
                                        - 28 production rules
                                        - 10 canonical presets
                                        - 3 problem categories
```

## 2. Key Features

- **Dual Inference Strategies:**
  - **Forward Chaining (Data-Driven):** Scans the rule base to a fixed point, deducing all reachable conclusions from supplied symptoms. Can identify multiple simultaneous faults (e.g., driver crash coexisting with thermal throttling).
  - **Backward Chaining (Goal-Driven):** Recursively evaluates candidate rules for a nominated hypothesis, asking only relevant questions and pruning irrelevant branches.
  - **Guided Problem Triage:** Backward chaining supports category-level triage (Network, Performance, Crash), automatically evaluating candidate hypotheses in sequence until a confirmed diagnosis is reached.
- **Partial Matching & Actionable Next Steps:**
  - When facts are insufficient to fire a multi-condition rule, the engine calculates **near matches** (rules where 1 or more conditions match and none are contradicted) and tells the user exactly which symptoms to verify next.
  - Intermediate hypotheses (sub-conclusions) are reported so progress is visible even before a final leaf diagnosis is concluded.
- **Bi-Directional Explainability:**
  - **HOW Facility:** Recursively traces the rule firings that established a conclusion, down to the original user-supplied inputs.
  - **WHY Facility:** Explains why a specific question is being asked during consultation by referencing the active goal and rule on the evaluation stack.
  - **WHY-NOT Facility:** When a hypothesis cannot be proven, the engine explains exactly which rule or condition failed and why.
- **Strict Rule Provenance:** All 28 production rules are derived from official industry technical documentation (Microsoft Support, Microsoft Learn, Google Public DNS, Dell Support) with verified URLs. No rules were hallucinated or generated by LLMs.
- **Dual Interfaces:** Provides both a responsive Single-Page Web GUI (with 1-click Quick Test Presets) and an interactive Terminal CLI.
- **Comprehensive Testing:** 36 automated unit tests (`pytest`) verifying knowledge integrity, multi-level chaining, unknown-answer handling, order independence, near-match detection, and cycle protection.

## 3. Quick Start

### Prerequisites

- Python 3.10+
- PowerShell / Terminal

### Setup

```bash
# 1. Activate virtual environment (Windows PowerShell)
.\.venv\Scripts\Activate.ps1

# (Or create a fresh virtual environment)
# python -m venv .venv
# .\.venv\Scripts\Activate.ps1
# pip install -r requirements.txt
```

### Option A: Launch Web Interface (Browser GUI)

```bash
python app.py
```

Open **http://localhost:5000** in your browser.

- Use **Quick Test Presets** to test 10 benchmark scenarios in one click.
- Switch between **Forward Chaining**, **Backward Chaining (Guided Triage or Single Goal)**, and **Knowledge Base Inspector**.

### Option B: Launch Terminal Interface (CLI)

```bash
python cli.py
```

Provides an interactive menu for:

1. Quick Test Presets (1-click scenarios)
2. Interactive Forward Chaining
3. Guided Backward Triage by Category
4. Targeted Backward Chaining (Single Hypothesis)
5. Rule & Citation Inspector
6. Built-in Test Suite Execution

### Option C: Run Automated Tests

```bash
pytest -v
```

Runs the full 36-test verification suite (executes in under 0.2s).

## 4. Knowledge Base Structure

- **30 Askable Facts:** Direct user observations (e.g., `power_light_on`, `can_ping_router`, `high_cpu_usage`).
- **4 Intermediate Hypotheses:** Derived internal states (`suspect_router_fault`, `suspect_local_config_issue`, `suspect_dns_issue`, `suspect_resource_heavy_process`) that enable multi-hop reasoning.
- **23 Diagnoses:** Concluded faults accompanied by prescriptive remediation guidance (e.g., `isp_outage`, `thermal_throttling`, `dhcp_failure`, `dns_failure`).
- **28 Production Rules:** IF-THEN rules with conjunctions and explicit negations (`!fact`). Unanswered facts are treated as unknown (`None`), avoiding fallacious closed-world assumptions.
- **10 Benchmark Presets:** Canonical symptom sets corresponding to standard IT support situations:
  1. Router Powered Off
  2. Router Hardware Fault
  3. ISP External Outage
  4. Single Device Config / DHCP Fault
  5. DNS Resolution Failure
  6. VPN DNS Conflict
  7. Thermal Throttling / Overheating
  8. Malware Infection
  9. Failing Storage Drive
  10. BSOD Graphics Driver Crash
